# Schematic Modify Toolkit Context

Programmatic helpers for editing existing KiCad schematics in place.

## Purpose

`schematic-modify` fills the gap between:

- `tools/schematic-gen/` (generates full new sheets from a structured spec)
- `tools/schematic-context/` (extracts + annotates context data from schematic files)

Use `schematic-modify` when you need to append/remove components or sheet links in an existing `.kicad_sch` without rewriting the whole file.

## Rule: load and save through `kicad_io`; no write while KiCad is open

Run every script here with `tools/.venv/bin/python` (Python 3.13, built from `tools/requirements.txt`). The rule itself is `tools/CONTEXT.md` "I/O-module Rule"; in this folder it means:

- **Every `.kicad_sch` and `.kicad_sym` load and save goes through `tools/kicad-io/kicad_io.py`.** `modify.py` does (`load_project` returns `kicad_io.Doc`s, `ProjectDocs.save_all` calls `kio.save_project`), so anything built on `modify` is covered. A script outside this folder puts `tools/kicad-io` on `sys.path` and imports `kicad_io` (see `tools/schematic-context/*.py`, `tools/schematic-gen/*.py`). Edits are made on the raw tree with `kicad_io`'s helpers, never through kicad-tools' typed objects. The splice save keeps every untouched item byte for byte, so a field edit is a few-line diff. A file keeps its KiCad version: a hidden field is written in the file's own form (`(hide yes)` in `effects` on KiCad 9, on the property on KiCad 10, and no second flag beside a bare kiutils `hide`).
- **Run with `KICAD_CLI` matching the sheets' KiCad version** (`tools/CONTEXT.md` "KiCad Version Rule"). v8 is KiCad 10 (since `v8-schematic-freeze-k10`), so its `--check` chain and any write run with `KICAD_CLI` on 10; the default is still 9.0.4, which can't load it. `STOCK_SYMBOLS` follows `KICAD_CLI`, so a part placed on 10 gets KiCad 10's stock symbol, and a `v8_*.py --apply` replayed on 10 no longer reproduces its historical (KiCad 9) output. `modify.ensure_lib_symbol` (through `kicad_io.check_embed`) refuses a library symbol from a newer KiCad than the target sheet, so a KiCad 9 sheet (v7, sensor boards, power supply) is written only with `KICAD_CLI` on 9.0.4.
- **No schematic write while KiCad has the project open.** `kio.save`/`save_project` (and so `ProjectDocs.save_all` and `annotate.py`) raise `KiCadOpenError` while a `~*.kicad_sch.lck` or `~*.kicad_pcb.lck` exists in the project folder, because KiCad would overwrite the script's changes on its next save. Call `kio.assert_not_open(path)` before any other write.
- History: until kicad10-tooling Phase 11 these tools used kiutils 1.4.8 through a shim (`kiutils_k9.py`, now deleted), because a bare kiutils load + save unhid every hidden field (v8 lost 536 fields; `docs/research/kicad-ai-tooling-2026-11/schematic-readability.md` §1). `tidy_fields.py` repairs that damage.

## Rule: readable placement, checked by `layout_check.py`

New parts must come out readable without a GUI pass (`docs/research/kicad-ai-tooling-2026-11/schematic-readability.md` §3.4). Parts already on a sheet are not moved by any of this, and the already-run v8 phase scripts (`v8_*.py --apply`) are not re-run.

- **`layout_check.py` is part of every `--check`.** `v8_debug_sheet.py --check` ends with it, so the whole v8 chain (Phases 8–11) runs it; a new phase script's `--check` calls `layout_check.run(ROOT)` and adds its return to its failure count. Per sheet it fails on: a visible field other than Reference/Value on a non-power symbol; any symbol body, visible text box or hidden-field anchor outside the paper; text-overlap pairs or stacked identical labels above the sheet's baseline in `layout_baseline.json`; a local, global or hierarchical label with no `justify` (no baseline: none allowed, Phase 11c); a **T-touch**, i.e. a wire end or pin end on the interior of a wire with no junction there (no baseline: none allowed, Phase 11c). A label anchor on a wire's interior is allowed (both tools connect it; KiCad's own save produces it by merging collinear wire segments) and is listed with `-v`. kicad-cli and the KiCad editor can disagree on whether a T-touch connects: on v8 TCA, kicad-cli kept R29's pull-up stub off `I2C_SCL_IN` where the editor joined them, so the netlist checks passed while the editor showed an SCL-to-pull-up short. A script must end a wire at the point it joins (or add a junction), never run a wire through another wire's end. Plain crossings of two wire interiors don't connect in either. The baseline only ratchets down: a lower count is reported, `--update-baseline` records it, and it never raises one (raise one only by hand, in a commit that says why). It prints the worst spots by sheet grid zone ("C3": rows A.. and columns 1.. every 50 mm from the 10 mm frame margin). v8 baseline at Phase 11b (after the 11a tidy): root 13, MCU 22, LED 5, power 51 (+ 6 stacked labels), TCA 50 overlap pairs; after the Phase 11c label pass: root 4, MCU 19, LED 5, power 39 (0 stacked), TCA 30; after the Phase 11c GUI autoplace: root 4, MCU 13, LED 3, power 19, TCA 6 (45 in all).
- **Text geometry** (calibrated on kicad-cli 9.0.4 SVG plots of v8: 141 modelled vs 143 plotted pairs; it holds on kicad-cli 10.0.8, where every field, label, sheet pin and text item plots in the same box and only pin texts, which this check doesn't model, moved 0.102 mm: kicad10-tooling SESSION, Worker #13 Notes). Characters are about 0.85 × the text height wide. A symbol field's angle and justification are in the symbol's frame and turn with the symbol. A label's text is horizontal at 0/180 and vertical at 90/270, justified as written. **A local label written without a `justify` is drawn centred on its anchor, across the wire end**: most labels written by the older scripts are like this.
- **`add_component`** places Reference and Value at the library symbol's own field offsets (position turned with the symbol; the library's angle, justification and font kept), as KiCad does on placement, and writes `(fields_autoplaced yes)` so KiCad re-autoplaces them when the part moves. Footprint, Datasheet and LCSC Part stay hidden at the origin.
- **Labels** (`_make_local_label`, `_label_angle`, used by `add_component` and `set_pin_net`): always horizontal. A horizontal stub's label reads outward along the stub; a vertical stub's label runs right of the wire, or left when the pin is left of the symbol's origin. Every label is written with KiCad's own justification (0/90: left bottom; 180/270: right bottom).
- **Existing labels: `tidy_labels.py`** (Phase 11c) applies the same label rule to labels already on a sheet, netlist-neutrally: a label with no `justify` gets one; on a single horizontal wire it reads away from the wire; on a single vertical wire it is turned horizontal, away from the part (`_label_angle`, using the pin at the wire's far end); with wires on more than one side, or none, it keeps its angle. Hierarchical and global labels get `left`/`right` only. Positions, text and kind never change; identical stacked labels (kind, text, position, angle) are reduced to one. It measures the result with `layout_check.py` on a scratch copy and flips any changed label in a new overlap pair; if a sheet's count would still go up it writes nothing. GUI autoplace moves fields, not labels, so this pass comes before it.
- **Stubs:** `WIRE_STUB_LEN` is 5.08 mm (was 2.54, where a vertical part's Value met the stub's label); `add_component(stub_len=...)` and `set_pin_net(stub_len=...)` override it per call.
- **Grid rule for future generator scripts** (row and grid placement of new parts): row pitch from the longest label or value in the row, about 0.75–0.85 × 1.27 mm per character (0.85 measured) + 2.54 mm, not a fixed 5–8 mm; every coordinate snapped to the 1.27 mm grid; new parts inside the frame, with a margin from the title block. Run `layout_check.py` after placing.

## Relationship to Other Tools

- **`schematic-gen`** is source-of-truth for generated sheets.
- **`schematic-modify`** performs surgical updates on existing sheets.
- **`schematic-context/annotate.py`** remains the single place that writes `ai_*` properties.

Design rule: this toolkit sets electrical properties (nets, footprint, LCSC fields) and delegates annotation to `annotate.py` after placement.

## Current Files

- `tidy_fields.py`: `--check | --apply`. Netlist-neutral field tidy for a whole project (default v8): hides every placed-symbol field except Reference and Value, restores `pin_numbers`/`pin_names` hiding on embedded library symbols (from v7 `c2acffc` for the same `lib_id`, else from the source library), and moves every `ai_*` field to its symbol's position. `--check` prints per-sheet counts (including visible text left off the paper) and writes nothing
- `v8_debug_sheet.py --fix-11c`: the Phase 11c one-off fixes (TCA T-touch, SW1 wire tail, Q20/Q21/U10 embedded symbols re-copied from the KiCad library to clear `lib_symbol_mismatch`); idempotent
- `v8_debug_sheet.py --fix-11f`: the Phase 11f (W3) fix: IC1 pin 4 onto `DATA_TO_LEDS_IC1` and R105 33 R to `DATA_TO_LEDS` (row m; v7 position modelled as a short). Saves only the LED sheet (a `save_all` would reformat every KiCad-saved sheet); idempotent
- `tidy_labels.py`: `--check | --apply` (`-v` lists each label). Netlist-neutral label justify pass and stacked-label dedupe for a whole project (default v8); see the placement rule above. Through `kicad_io`, refuses while a `~*.lck` exists
- `layout_check.py`: read-only readability check for a whole project (default v8): visible extra fields, off-paper items, labels with no justify, T-touches, overlap and stacked-label counts against `layout_baseline.json` (ratchets down; `--update-baseline`), worst grid zones; `-v` lists every pair. See the placement rule above
- `layout_baseline.json`: the committed per-sheet baseline (`overlap_pairs`, `stacked_labels`), keyed by `<root sheet stem>/<sheet path relative to the root sheet's folder>`, so `--root <scratch copy>` checks against the same baseline; `--update-baseline` refuses a root outside the repo. The `v8_*.py` scripts take `--root <copy>/motion-play-main-v8.kicad_sch` (and `v8_project_setup.py` takes `--root`) to run on a scratch copy: with `--check`/`--verify` on any copy, and with a mode that writes (`--apply`, `--erc-fixes`, `--fix-11c/f`, `--annotate`) only on a copy outside the repository (a replay); the working tree is written only without `--root`
- `modify.py`: reusable helpers (`add_component` (with `project_name`), `remove_component`, `add_hierarchical_label`, `add_sheet_reference`, `annotate_components`, `pin_position`, `set_pin_net`, `remove_no_connect_at`, `remove_junction_at`, `add_local_label`, `add_wire`, `rename_hlabel`, `rename_sheet_pin`, and from Phase 10 `remove_component_with_stubs`, `set_property`, `add_power_symbol`). A power symbol's Value names its global net in KiCad 9 (checked on the v8 project), so `add_power_symbol` and a Value edit retarget a rail. `pin_position` handles 0/90/180/270-degree symbols (fixed 2026-11-03: 90/270 used to put pins at the wrong end; mirrored symbols still raise). `set_pin_net` moves a label-wired pin to another net (renames the stub's label, or replaces a no-connect with a label); it refuses pins wired into a network
- `v8_project_setup.py`: v8-debug-board initiative. Copies the v7 project (`c2acffc`) to `hardware/pcb-main-v8/kicad/` as `motion-play-main-v8`, renames instance project names on the raw tree through `kicad_io`, writes an empty stackup-only `.kicad_pcb`, and verifies (ERC, netlist vs v7, DRC load). `--verify --no-v7-compare` re-runs the checks after edits
- `v8_mcu_sheet.py`: v8-debug-board Phase 8. U3 pin moves and jumper rows a, e, g on `esp32_s3.kicad_sch` (JP1/JP2 1x4 headers, J10 + JP3/JP4 external master, JP5 SJ3), `+3.3V_BUS` sheet pin, IC1 swap to SN74AHCT1G125 on `led_controller.kicad_sch`. All label-style, so no GUI wiring. `--check` exports the netlist and checks pin -> net against the GPIO allocation and the all-v7 jumper positions against v7 @ `c2acffc` (it also applies later phases' jumpers by importing `v8_bus_sheet.py`)
- `v8_bus_sheet.py`: v8-debug-board Phase 9. TCA sheet (now A3): row b (47 Ω + bypass header per channel line, TPD2E2U06 + GND-leg header per connector, CHn_x / CHn_x_CONN split by renaming the channel hierarchical labels), row d (2x3 upstream selector headers, R28/R29 moved off the bus, 4.7 k/10 k options, downstream 4.7 k + open SJ2), row f (BQ_SDA/BQ_SCL headers; U5 relabelled on the power sheet; root sheet pins), channel test points + ground points. Wire-wired pins are freed by removing the wire/junction first, then labelled. `--check` = MCU check + pin -> net + each jumper's positions
- `v8_debug_sheet.py`: v8-debug-board Phase 11. Debug features (test points + ground points, debug LEDs, UART0 and spare-GPIO headers). `--check` = Phase 8–10 checks + Phase 11 pins, BOM audit, ERC summary, then `layout_check.py` (Phase 11b): the end of the whole v8 check chain
- `v8_power_sheet.py`: v8-debug-board Phase 10. Power sheet modified in place from `tools/schematic-gen/power_v8_spec.json` (paper A3, new parts gridded): battery block (J8 XT30, F3, Q20/Q21, gate network, SW4, J9) replacing BT1/Q2/R33/R34; rows c, h, i, j, k, l; STAT LED; PMID 6 x 22 uF; rail test points + GND points; J7 on a v8 shell-GND footprint (`libraries/footprints/motion-play-v8.pretty`). Rails: global +3.3V -> +3.3V_MCU; bus loads on the global +3.3V_BUS; D5 on +5V_CORE; link h4 on the LED sheet ahead of v7's R27. `--check` = Phase 8 + 9 checks + pin -> net for every power part + each power row's positions. The all-v7 comparison drops BT1/Q2/R33/R34 (v7) and the new battery parts (v8), both modelled conducting: battery protection has no v7 position (user decision 2026-11-03)

## Typical Workflow

1. Run an initiative's script built on `modify.py` (for example `v8_bus_sheet.py --apply`) to place components/sheet refs off to one side.
2. Script calls `tools/schematic-context/annotate.py` for `ai_*` properties.
3. Open KiCad and do manual placement/wiring cleanup.
4. Run `tools/schematic-context/extract.py --previous` to refresh `circuit-context.json`.

# Hazards

Known traps that waste a session's time. One trap per entry; the Gardener removes an entry once its cause is fixed.

- **Never load or save a KiCad file with anything but `tools/kicad-io/kicad_io.py`.** kiutils (removed in kicad10-tooling Phase 11) unhid every hidden field on a KiCad 8/9 schematic load + save (536 fields on v8; `docs/research/kicad-ai-tooling-2026-11/schematic-readability.md` §1) and made KiCad 9 boards unloadable (v8-debug-board PLAN OQ-11). A plain kicad-tools save rewrites the whole file's layout, and its typed `PCB` silently rebases coordinates and fills in defaults. `kicad_io` splice-saves, keeps the file's version, refuses while KiCad has the project open, and checks the kicad-tools pin; run the tools with `tools/.venv/bin/python`. Rule: `tools/CONTEXT.md` "I/O-module Rule".
- **kicad-tools writes a Python float atom with 6 significant digits.** An atom built as `SExp(value=181.6099)` saves as `181.61` (and `63.123456789` as `63.1235`), so a coordinate moves silently. Set every number as text with `kicad_io.set_num`/`node()` (`kio.num` gives the exact shortest text), never as a bare float. Evidence: kicad10-tooling SESSION, Worker #5 Notes; tested in `regress.py iotest` stage 5.
- **pip on Python 3.7 can't find matplotlib wheels for this macOS.** pip 20.0.2 sees no wheel and tries a source build. Upgrade pip to 24.0 (the last version for 3.7) first; matplotlib 3.5.3 then installs. Done once in the user's pyenv 3.7.3 on 2026-11-02 (v8-debug-board Phase 5); see `tools/pcb-context/requirements.txt`.
- **kicad-cli 10 writes the project's `.kicad_prl` on read-only commands.** `kicad-cli sch export netlist` (10.0.8) creates or rewrites the `.kicad_prl` beside the root sheet; 9.0.4 doesn't. `.kicad_prl` is gitignored, so `git status` won't show it. Run kicad-cli 10 only on scratch copies, never on `hardware/pcb-main/kicad/` (v7) or another KiCad 9 project folder. Evidence: kicad10-tooling SESSION, Worker #1 Notes.
- **With `KICAD_CLI` on KiCad 10, the tools take KiCad 10 stock symbols, which can't go into KiCad 9 sheets.** `STOCK_SYMBOLS` follows `KICAD_CLI`, so a `v8_*.py --apply` (or any `modify.add_component`) on a KiCad 9 sheet would embed KiCad 10 syntax, and kicad-cli 9 then drops the sheet's contents and exits 0. The I/O module refuses (`KiCadIOFormatError`, `kicad_io.check_embed`); run write modes on KiCad 9 sheets with `KICAD_CLI` on 9.0.4. Evidence: kicad10-tooling SESSION, Worker #13 Notes task 3; tested in `regress.py iotest` stage 4b.
- **Files saved by KiCad 10 can't be opened by KiCad 9; never open v7 (`hardware/pcb-main/kicad/`) in KiCad 10 and save.** A KiCad 10 save converts the file to 10's format with no way back, and v7 is cited at `c2acffc` and is never re-saved. Only v8 is on KiCad 10; which board is in which format: `hardware/CONTEXT.md` "KiCad Versions".
- **`pcbnew` from KiCad 10's Python silently saves a KiCad 9 board as KiCad 10.** `SaveBoard` writes format 20260206 with no warning, so a script run on v7 or a sensor board converts it. A board writer must refuse any board not already in KiCad 10's format (`tools/CONTEXT.md` "Board write path"). Evidence: kicad10-tooling SESSION, Worker #15 Notes.
- **`KICAD_CLI` still defaults to KiCad 9.0.4, and v8 is KiCad 10.** Run without `KICAD_CLI` set to KiCad 10's kicad-cli, v8's checks and extracts fail to load the sheets or board, which looks like a broken tool. Set `KICAD_CLI=/Applications/KiCad10/KiCad.app/Contents/MacOS/kicad-cli` for v8 (`tools/CONTEXT.md` "KiCad Version Rule").
- **kicad-cli rewrites the user's KiCad settings unless `KICAD_CONFIG_HOME` points at a scratch folder.** Even a read-only run (`kicad-cli version`, an ERC) writes `kicad_common.json` (and creates `kicad.json`, `colors/`) under `~/Library/Preferences/kicad/<version>/` on exit. Set `KICAD_CONFIG_HOME=<scratch>`, seeded for KiCad 10 with `/Applications/KiCad10/KiCad.app/Contents/SharedSupport/template/{sym,fp}-lib-table`. Evidence: kicad10-tooling SESSION, Worker #16 Notes and the Orchestrator's verification after it.
- **KiCad 10 writes a `.history/` folder, a nested git repo, into the project folder on GUI save (Project Backup).** `.gitignore` ignores `.history/` everywhere; never `git add -f` it (a nested `.git` becomes a broken submodule entry). It can be turned off under Preferences → Common → Project Backup. Evidence: kicad10-tooling SESSION, Worker #18 Notes.
- **The user's KiCad 10 global library tables point at the app's own tables by path.** `~/Library/Preferences/kicad/10.0/{sym,fp,design-block}-lib-table` each hold one nested entry to `/Applications/KiCad10/KiCad.app/Contents/SharedSupport/template/…`, not a copy. Moving or renaming the app (for example to `KiCad.app` when 9 is uninstalled) breaks stock-library resolution in the GUI. v8's own libraries resolve through its project tables and aren't affected.
- **macOS deletes files under `/private/tmp` untouched for about 3 days, including the Claude Code scratchpad.** An initiative that waits days on a user gate loses its scratch venvs, boards and scripts. Keep anything needed after a gate as a rebuild script or under a gitignored repo path. Evidence: kicad10-tooling SESSION, Worker #19 Notes ("Stage A rebuilt").

# Hazards

Known traps that waste a session's time. One trap per entry; the Gardener removes an entry once its cause is fixed.

- **Never load or save a KiCad file with anything but `tools/kicad-io/kicad_io.py`.** kiutils (removed in kicad10-tooling Phase 11) unhid every hidden field on a KiCad 8/9 schematic load + save (536 fields on v8; `docs/research/kicad-ai-tooling-2026-11/schematic-readability.md` §1) and made KiCad 9 boards unloadable (v8-debug-board PLAN OQ-11). A plain kicad-tools save rewrites the whole file's layout, and its typed `PCB` silently rebases coordinates and fills in defaults. `kicad_io` splice-saves, keeps the file's version, refuses while KiCad has the project open, and checks the kicad-tools pin; run the tools with `tools/.venv/bin/python`. Rule: `tools/CONTEXT.md` "I/O-module Rule".
- **kicad-tools writes a Python float atom with 6 significant digits.** An atom built as `SExp(value=181.6099)` saves as `181.61` (and `63.123456789` as `63.1235`), so a coordinate moves silently. Set every number as text with `kicad_io.set_num`/`node()` (`kio.num` gives the exact shortest text), never as a bare float. Evidence: kicad10-tooling SESSION, Worker #5 Notes; tested in `regress.py iotest` stage 5.
- **pip on Python 3.7 can't find matplotlib wheels for this macOS.** pip 20.0.2 sees no wheel and tries a source build. Upgrade pip to 24.0 (the last version for 3.7) first; matplotlib 3.5.3 then installs. Done once in the user's pyenv 3.7.3 on 2026-11-02 (v8-debug-board Phase 5); see `tools/pcb-context/requirements.txt`.
- **kicad-cli 10 writes the project's `.kicad_prl` on read-only commands.** `kicad-cli sch export netlist` (10.0.8) creates or rewrites the `.kicad_prl` beside the root sheet; 9.0.4 doesn't. `.kicad_prl` is gitignored, so `git status` won't show it. Run kicad-cli 10 only on scratch copies, never on `hardware/pcb-main/kicad/` (v7) or another KiCad 9 project folder. Evidence: kicad10-tooling SESSION, Worker #1 Notes.
- **With `KICAD_CLI` on KiCad 10, the tools take KiCad 10 stock symbols, which can't go into KiCad 9 sheets.** `STOCK_SYMBOLS` follows `KICAD_CLI`, so a `v8_*.py --apply` (or any `modify.add_component`) on a KiCad 9 sheet would embed KiCad 10 syntax, and kicad-cli 9 then drops the sheet's contents and exits 0. The I/O module refuses (`KiCadIOFormatError`, `kicad_io.check_embed`); run write modes on KiCad 9 sheets with `KICAD_CLI` on 9.0.4. Evidence: kicad10-tooling SESSION, Worker #13 Notes task 3; tested in `regress.py iotest` stage 4b.

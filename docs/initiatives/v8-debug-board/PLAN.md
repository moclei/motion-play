# v8 Main Board — Debug Board — Plan

## Approach

Four strands, run in sequence in one initiative. They share one board model and one design-intent file.

1. **Power-path investigation (desk → bench → design).** Workers trace v7's battery and power path from the schematic and the datasheets. They root-cause the BQ24195 "needs I²C" fault and rank the mechanisms by which battery connection could cook a board. They then write a bench relay for the Debugger (`debugger/RELAY-power.md`). The Debugger runs the bench work on #0001, #0002 and #0004 as lab cards, outside this initiative. The v8 power design (Phase 7) is gated on those findings (wait **W1**).
2. **v8 design intent and schematic.** One design-intent file, `hardware/pcb-main-v8/CONTEXT.md`, holds every v8 decision: the GPIO allocation, the jumper matrix (with v7 and v8 positions), the test-point and ground-point list, debug LEDs, part choices, and inherited v7 faults with their fixes. The schematic is built from it with the schematic tools. Workers can't do some schematic steps (wiring and Update-PCB-from-schematic are GUI-only today), so those become user steps with exact instructions.
3. **Board model (audit phases 1–2).** `kicad-extraction-audit.md` §5–§6.1 is the spec: one parser and one model, with zones (de-fractured fills), stackup, true pad polygons, bodies, outline, net topology and provenance. Reports are derived from the model: net-centric, plane/region, and per-net PNGs. It is validated on v7 against the audit's fixture table. This model then feeds both the AI layout work and the partner review. It absorbs the queued `pcb-board-model` initiative (decisioning §3.2a row 2) and supersedes the never-run `routing-verification` initiative.
4. **AI layout, learning as we go.** Placement and routing are trialled in small, reviewed steps. Each step follows the same loop: Worker writes a placement or routing with a script, then the user reviews it and corrects it in KiCad. A Worker reads the user's corrections back (live over IPC while the board is open, then a board-model before/after diff once it is saved) and turns each correction into a rule in `tools/pcb-context/` (rules config and CONTEXT). The next step runs with the updated rules. Placement goes block by block, then the whole board. Routing is tentative: AI routes the low-risk nets, and the user owns the nets in OQ-1.

Review before ordering = the user's review + an AI partner review answered from board-model output (no throwaway probes), with targeted questions fixed in advance (Technical Notes). DRC/ERC clean. Then fab outputs, preflight (stock, BOM/CPL), user places the order (**W-order**).

**Partner review: targeted questions (Phase 18).** (1) Every member of each SDA/SCL net, its route, neighbours within the audit radii, and reference plane, in each jumper position. (2) What protects each cable-facing line, and where. (3) Battery → charger → boost → LDO path vs the Phase 2/7 failure mechanisms. (4) For each jumper in its v7 position, the net topology matches v7's (schematic level; the copper is new by design). (5) Every test point has a ground point within spring reach. (6) Antenna keepout, USB pair, switching loops.

**Board-model decisions (audit §6.1).** Generated outputs are committed with `_provenance` (tools/CONTEXT.md Source-Hash Rule), beside the PCB in `<kicad folder>/board-model/` (model, net and plane reports, `img/` PNGs), generated from the repo path so `--fresh` can re-hash the source. The stale v7 `pcb-layout-context.json` / `drc-report.json` are marked historical, not deleted (the debug track cites `c2acffc` files). Reads go through `tools/kicad-io/kicad_io.py` (kicad-tools 0.29.0 raw layer; board readers use `pcb_raw.py`, never kicad-tools' typed `PCB`) plus kicad-cli 10. Board writes go through `pcb_write.py` (AI layout tooling below). On a KiCad 10 board `board_model.py` matches its KiCad 9 output apart from format items (kicad10-tooling Phase 13; `tools/pcb-context/README.md` "KiCad 9 and 10 boards"). Definitions (high-current, high dv/dt, neighbour radii, edge-to-edge clearance), plus driver pads and critical nets, go in a per-board config file, `tools/pcb-context/board-config/<pcb stem>.json` (picked up by stem), seeded from audit §6.1. Net topology follows KiCad's connectivity rule: an anchor of one item inside the other's copper.

**AI layout tooling.** Placement logic generalises `place_power.py`, but not its text-edit write path (it rewrites only the footprint's `(at …)`, right for pure moves only, and writes outside `kicad_io` and its lock guard); `place_power.py` is deleted once `place.py` covers its logic, with its exception in tools/CONTEXT.md's I/O-module Rule. `place.py` reads the board model and the rules config and emits one JSON op list (ref → x, y, rotation, side). Two consumers take that op list:
- **Batch writer, `tools/pcb-context/pcb_write.py`** (OQ-3, user-confirmed 2026-11-20). KiCad 10's own `pcbnew`, run with KiCad 10's bundled Python (`/Applications/KiCad10/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3 -I`, 3.9.13, pcbnew 10.0.8), headless; the only code that imports `pcbnew`. It writes placement, Phase 16's tracks and vias, and zone refill. Guards on every write: refuse a board whose format isn't KiCad 10's (pcbnew 10 silently saves a KiCad 9 board as 10: HAZARDS); refuse while a `~*.kicad_pcb.lck` exists; afterwards kicad-cli 10 must load the board and run DRC, and a board-model before/after check, keyed by footprint ref and geometry (segment and via ids are positional and change after pcbnew's first save), must show only the named footprints changed and the netlist unchanged. The round trip is not byte-identical on the first pcbnew save of a kicad-cli-converted board: every track is regrouped by net once (v7: +10,444 lines), and from then on it is a fixed point. v8's board has no tracks yet, so it doesn't show there; on a v7 test copy, "empty op list ⇒ byte-identical" holds only from the fixed point. Footprints enter v8's board through KiCad's Update PCB from Schematic, never the writer. Evidence: kicad10-tooling PLAN "Board write path", SESSION Worker #15 Notes; tools/CONTEXT.md "Board write path".
- **Live channel, `tools/pcb-context/pcb_live.py`** (kicad10-tooling G4). kipy (kicad-python 0.8.0, pinned in `tools/requirements-kipy.txt`, venv `tools/.venv-kipy`) over KiCad's IPC API, with KiCad 10 open on the board and the API server enabled (already on in the user's prefs). For the W4–W5 placement reviews: the AI pushes the op list into the open board, one named commit (undo step) per block, so the user watches and can undo; the user corrects by hand; the AI reads the positions back with `get_footprints` into the placement report. Nothing reaches disk until the user saves; then the file is checked with kicad-cli 10 DRC and the ref-keyed board-model diff. Don't call kipy's `check_version()` (raises on 10.0.8). Trial: tens of ms per edit, 0 busy, the saved file matched pcbnew's to 1 nm (kicad10-tooling PLAN Trials "IPC outcome"; tools/CONTEXT.md "Live board edits"). Live track writes and hand-routing read-back (`get_tracks`/`get_vias`) are untested: Phase 16 probes read-back before W6 relies on it. No MCP server (kicad10-tooling G5).

Our tools read and compute on Python 3.13 in `tools/.venv` through `kicad_io` and `pcb_raw.py`. `pcbnew` is removed in KiCad 11 (around early 2027), so `pcb_write.py` stays one module behind the op-list interface: its body moves to IPC if KiCad 11 serves it headless, else to kicad-tools raw edits through `kicad_io` (proven for copper geometry, but needs KiCad's field-angle rule on flips; kicad10-tooling Deferred). The rules config holds constraints that can be checked (keepouts, decoupling distance, test-point spacing, connector edges). Placement runs: board model in → placement → write (batch or live) → board-model check (overlaps, courtyards, rules) → render PNG → user review. The user's corrections are measured as a before/after diff of positions only (kipy read-back while the board is open, the board-model diff after save), so this needs no diff mode.

**KiCad 10 (since kicad10-tooling).** v8 is KiCad 10 since tag `v8-schematic-freeze-k10` (pushed); `v8-schematic-freeze` / `-k9` is the KiCad 9 rollback point. KiCad 9.0.4 stays installed for v7, the sensor boards and the lab, which stay KiCad 9 files (HAZARDS: KiCad 10 files can't be opened by 9). When `KICAD_CLI` is unset, the tools pick kicad-cli by the target file's format (Phase 13, user decision 2026-11-20); `KICAD_CLI` still overrides. Every kicad-cli run uses a scratch `KICAD_CONFIG_HOME` seeded with KiCad 10's default lib tables (tools/CONTEXT.md KiCad Version Rule). ERC baseline on 10: 0 errors; 81 `pin_to_pin`, 2 `lib_symbol_issues` (J7, U5), 5 `same_local_global_label`, 19 `lib_symbol_mismatch` (TH1 + 18 solder jumpers, accepted at kicad10-tooling G3: no "Update symbols from library"). The `v8_*.py --check` chains pass on 10; an `--apply` replayed now places KiCad 10 stock symbols and doesn't reproduce its historical output.

**Firmware.** A `motion-play-v8` env with the pin set chosen at build time to match jumper (a), plus a v8 diag image. No v7 env changes.

**Schematic readability (Phases 11a–11f, replan 2026-11-04).** kiutils 1.4.8 doesn't parse KiCad 8/9's `(hide yes)`, so every script load/save of a KiCad-saved sheet unhid its fields (536 on v8), and `annotate.py` put new `ai_*` fields at (0, 0): 1,616 overlapping text pairs (`docs/research/kicad-ai-tooling-2026-11/schematic-readability.md` §1). ## Rejected Approaches
- Separate `pcb-board-model` initiative run first: folded in, because v8 layout and review are its only consumer now and the user wants one initiative at a time.
- Targeted review via throwaway kiutils probes only: user wants reusable scripts for partner review.
- Fixing the BQ fault in firmware only (current `configureBQ24195()`): the brief asks for a design root cause.
- Board-model topology joining a track to a pad only when the track endpoint lies inside the pad: split 6 v7 nets that KiCad (DRC: 0 unconnected) treats as connected; replaced by the anchor-inside-copper rule.
- Plane voids computed by subtracting a buffered split channel between fills: left thin slivers reported as voids; replaced by classing an empty region that touches fills of two nets as a split gap.
- Swapping the BQ24195 for a standalone (no-I²C) charger (Phase 1 option 4): rejected in Phase 7, because it takes the BQ off the bus and no jumper position could then rebuild v7's bus membership (row f).
- Regenerating the v8 power sheet with `generate_power_sheet.py` from `power_v8_spec.json` (Phase 10): it would drop the v7 parts the spec leaves out (U9, D1/R1, TP1–TP4, C7/R27 on the LED rail) and every v7 symbol/footprint choice; replaced by an in-place edit (`v8_power_sheet.py`).
- Bare kiutils `Board` writes for `place.py` (OQ-11, Phase 11a): a load + save of a KiCad 9 board drops footprint field state, locks, via `free` and uuids, and kicad-cli 9.0.4 can't load the result.
- Switching from kiutils to kicad-sch-api to escape the `(hide yes)` bug (Phase 11 replan): needs Python 3.10+ and a port of every tool; a 40-line shim fixes it.
- KiCAD-MCP-Server (Avinash1286) autoplace/declutter tools for the tidy: unvetted, source not visible, writes files directly; our own tidy plus a netlist gate instead.
- `layout_check.py` on the prototype probe's geometry (field angle taken as on screen, every label anchored at its start, 0.72 × height per character): differs from KiCad's plot for rotated fields, sheet pins and labels with no justify (drawn centred); replaced by geometry calibrated on kicad-cli SVG plots (Phase 11b).
- Sheet-pin nets from a probe pin placed only on the sheet pin itself (Phase 12a): where a sheet pin lies inside a root wire (power-supply board), KiCad joins pin and wire, but a probe on that point splits them, so the probe's net was half the real one; replaced by accepting a probe only when its members equal one real net's full set, retrying at the wire's ends and then the child's label.
- OQ-3 option 2, surgical text edits of the footprint `(at …)` (what `place_power.py` does): right for pure moves only; a rotation or flip redoes KiCad's math by hand, and tracks would be hand-written s-expressions. `pcbnew` on KiCad 10 chosen instead (user, 2026-11-20).
- OQ-3 option 3, a kiutils board shim: kiutils is removed from `tools/` (kicad10-tooling Phase 11), and the board lost a dozen kinds of data in it (OQ-11).
- OQ-3 option 4, KiCad IPC (kipy) as the batch writer: needs the GUI open with the API on for every write, which doesn't suit unattended Worker runs; kept only as the live channel for the W4–W5 reviews (kicad10-tooling G4). Revisit for batch writes at KiCad 11 (headless).
- OQ-3 option 5, a board writer of our own: option 3's work and more, with nothing reused.
- kicad-tools raw edits through `kicad_io` as v8's board writer (kicad10-tooling Phase 13 candidate b): byte-identical round trip and copper identical to pcbnew, but our flip got KiCad's field angles wrong (and a first attempt flipped the layer twice); kept as the KiCad 11 fallback.
- kicad-mcp-pro as the live board channel (kicad10-tooling G5): its reads lose rotation and anything under 0.01 mm, its edits aren't named undo steps, write mode can't be limited to moves, about $0.2 and 13–35 s per turn; no MCP server is used.

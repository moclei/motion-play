# KiCad 10 Tooling — Plan

## Approach

Change one thing at a time, and compare each step against a baseline taken before it.

1. **Install and baseline (KiCad 9 still the reference).** KiCad 10.0.8 goes in next to 9.0.4. The tools run on Python 3.7 against KiCad 9 to record reference outputs, then again on the 3.13 venv, still against KiCad 9 files. That separates the Python change from the KiCad change. (Phases 1–2, done.)
2. **KiCad 10 file compatibility (Phase 3, done).** Scratch copies of v8 and v7 converted to KiCad 10; netlists compared; kiutils, kicad-tools and kicad-sch-api round-trip surveys. At G2 the user chose the 3.13 venv and **replacing kiutils with kicad-tools in full**.
3. **Port the tools to kicad-tools, still on KiCad 9 (Phases 4–11).** Change the parser only: `KICAD_CLI` stays on 9.0.4 and every input is a KiCad 9 file, so any output difference is the port's fault. First the groundwork (a committed regression harness, checks that run on scratch copies, kicad-tools pinned in the venv, and the tag `kicad10-preport` as the oracle). Then an API spike that tests kicad-tools' editing API before anything is ported (user gate G2a, done: every writer and board reader goes on kicad-tools' raw s-expression layer with our own helpers, files are saved with a splice save, and three v7-only scripts are deleted). Then the port: the I/O module (Phase 6a), `modify.py` (6b), then one group of tools per phase, each checked against the same command run by the `kicad10-preport` tools on the same input. Then kiutils is removed.
4. **Re-validate on KiCad 10 (Phases 12–13).** The ported tools on KiCad-10 scratch copies with `KICAD_CLI` set to 10: the schematic tools first, then the board tools and the board write path (OQ-3). The gate is the one v8 Phase 11a used: identical netlist (only the date, tool-version and file-format lines may change), ERC errors unchanged, and layout_check at or below its baseline.
5. **Migrate v8 (user gate G3, Phase 14).** Only after the tools pass on a scratch copy. The project files are converted on the branch, the checks are re-baselined, circuit-context is re-extracted, and a KiCad-10 freeze tag is cut.
6. **Trials (gates G4, G5; Phases 15–16).** Live IPC through kipy, then one MCP server. Both run on scratch copies and on the same small task, so they can be compared. Each ends in keep or drop.
7. **Close (Phase 17).** Docs, hazards, and a v8 resume note for the Planner.

**Python (OQ-1, decided at G2).** The KiCad tools run in `tools/.venv` on `/usr/local/bin/python3.13`, built from the committed `tools/requirements.txt`. Phase 2 proved parity on KiCad 9 files (21/21 reference hashes, board model exact). Once the port starts the tools need Python ≥ 3.10 (kicad-tools), so they no longer run on the global 3.7. The global `python3` and the lab pre-commit hook don't change; the hook runs only `tools/lab/precommit.py`. Known churn: `render.py` PNGs regenerated on matplotlib 3.11 differ from the committed v7 ones in text pixels only. The pcbnew writer (OQ-3) runs on KiCad's bundled Python.

**Parser (OQ-2, decided at G2): kicad-tools replaces kiutils in full.** Phase 3 showed kicad-tools 0.29.0 round-trips every file tree-identically: all ten converted sheets, both converted boards, and v7's KiCad 9 sheets and board. Its typed `PCB` reads KiCad 10's name-only nets.
- **Which layer (G2a, decided).** Every tool that writes, and every board reader, works on kicad-tools' raw s-expression layer (`kicad_tools.sexp.SExp` trees from `core.sexp_file`) through the I/O module and our own helpers. The typed views (`schema.Schematic`, `schema.SymbolLibrary`, `schema.PCB`) may be used only as read-only conveniences, in tools that never save, wrapped around a `Doc`'s tree. Never use them to write: the typed objects are snapshots with no edit or remove, `add_symbol`/`add_label` place fields and justify differently from `modify.py`, and `embed_lib_symbol` and `SymbolProperty.to_sexp` rebuild what they write. Board readers don't use the typed `PCB` at all: it silently rebases coordinates onto the Edge.Cuts corner and substitutes defaults (SESSION Worker #5 Notes task 3). Evidence: the Phase 5 raw-layer prototype of every public `modify.py` operation matched preport on netlist, ERC and plotted strings, 11/11 on KiCad 9 and 8/8 on KiCad 10 (SESSION Worker #5 Notes tasks 1–3; prototype `ktmod.py` in the session scratchpad `p5/scripts/`, if still present).
- **Pin and upgrades.** `kicad-tools==0.29.0`, the version Phase 3 tested, with every transitive package pinned in `tools/requirements.txt` (it pulls in about 73 packages). No upgrade during this initiative unless a bug blocks the port. An upgrade is a commit of its own: build a second venv with the new pin, run the regression harness with the old venv and the new one, and run every `--check` chain. Any difference blocks the upgrade until it's explained. The harness also round-trips v8, v7 (`c2acffc`) and the other boards' files and checks they are tree-identical. The I/O module checks the installed version against the pin, so a venv built from a different file fails loudly.
- **One I/O module: `tools/kicad-io/kicad_io.py`** (G2a, from SESSION Worker #5 Notes task 5). It replaces `kiutils_k9.py` and is the only place that loads or saves a KiCad file; nothing else under `tools/` calls kicad-tools' loaders or savers. It has a folder of its own because `schematic-*`, `pcb-context` and `kicad-regress` all use it; tools put `tools/kicad-io` on `sys.path`, as they do for `kiutils_k9` today. Phase 6a builds it; the kiutils Rule in `tools/CONTEXT.md` becomes a rule about this module in Phase 11.
  - **Pin check, at import.** `importlib.metadata.version("kicad-tools")` must equal `PIN = "0.29.0"`, or it raises `KiCadIOVersionError` naming `tools/requirements.txt`.
  - **Format check, at load.** Each file kind has the set of format versions the harness has tested: schematic 20250114 and 20260306, board 20241229 and 20260206, symbol libraries as found in the KiCad 9.0.4 and 10.0.8 stock libraries (20241209, 20251024). Phase 6a added the KiCad 8 formats of the power-supply project (schematic 20231120, board 20240108), which the harness round-trips and Phase 11 must read, and the symbol-library formats of the project libraries the tools load (20211014 for the easyeda2kicad parts in `resources/`, which v8's `sym-lib-table` names, and 20231120); the Phase 6a test round-trips each. Any other version (a KiCad 11 file, say) raises rather than being edited blind.
  - **Load.** `load_schematic(path)`, `load_symbol_lib(path)` and `load_board(path)` each return a `Doc`: path, kind, the raw `SExp` tree, the original text, the per-item source spans, and the format version. The version lives on the `Doc`, not in a module global, because the helpers write a property's hide flag differently on 9 and 10.
  - **Save.** `save(doc, path=None)` runs the lock guard; refuses if the tree's format version differs from the one loaded (a KiCad 9 file can't leave as 10); writes with the splice save (below), atomically (`core.atomic_write.atomic_write_text`), with a final newline. `save_project(docs)` saves several docs after one guard check, as `ProjectDocs.save_all` does today.
  - **Splice save (OQ-7, decided at G2a).** kicad-tools records each top-level item's source span at parse. At save, a top-level item whose serialization is unchanged is written as its original text, with the original whitespace before it; a changed or new item is serialized by kicad-tools. The result must be tree-identical to a plain kicad-tools save. Same code for KiCad 9 and 10, schematics and boards, with no kicad-cli. Cost: the touched item takes kicad-tools' layout (short lists on one line) until KiCad next saves the file. Phase 5 measured a one-Value edit at +4/−8 lines against +548/−1,467 for a plain save. It wasn't measured on a board edit; Phase 6a's test covers one.
  - **Lock guard.** `lock_files(path)` and `assert_not_open(path)` raise `KiCadOpenError` while any `~*.kicad_sch.lck` or `~*.kicad_pcb.lck` exists in the project folder (today's rule, extended to boards). kicad-tools' own `check_kicad_lock` looks only at the one file's marker and only warns, so the module doesn't rely on it.
  - **Raw-tree helpers** (about 170 lines with the I/O, from the prototype): `kids`, `child`, `atom`, `at_xy` to find; `set_str`, `set_bare`, `set_num` to set atoms; `node(text)` to build an item from KiCad-form text; `insert_item` (keeps KiCad's top-level order) and `remove_items`; version-aware `make_property`, `is_hidden`, `hide`; `to_lists(tree)` for `layout_check`. Board accessors live in `pcb-context` (Phase 10), not here.
- **Oracle.** The tag `kicad10-preport` (cut at the end of Phase 4) is the pre-port toolset. Every port phase runs the same command with the `kicad10-preport` tools (from a `git worktree`, in `tools/.venv`, which keeps kiutils until Phase 11) and with the ported tools, on fresh copies of the same KiCad 9 input, with `KICAD_CLI` on 9.0.4. **Read tools:** identical output (JSON compared leaf by leaf, floats within Phase 2's 1e-9 mm, timestamps and `_provenance` excluded). **Write tools:** identical kicad-cli netlist (structural compare), ERC counts by type and plotted strings per sheet. Their file text will differ, because kiutils drops tokens that kicad-tools keeps.

**Raw-layer traps the port must handle (Phase 5).**
- **Float atoms.** An atom built as `SExp(value=x)` from a Python float is written with 6 significant digits (`181.6099` → `181.61`). Every number goes through `set_num`/`node()` with explicit text, never a bare float.
- **Hide flags, three forms.** A property's hide is `(hide yes)` inside `effects` (KiCad 9 as KiCad writes it), a bare `hide` inside `effects` (files last saved by kiutils, such as v8's LED sheet), or, on KiCad 10, `(hide yes)` on the property itself, before `effects`, beside `(show_name no)` and `(do_not_autoplace no)`. Readers accept all three; writers write the loaded file's own form (from `Doc`'s version) and never add a second flag beside an existing one. The same applies to `(pin_numbers (hide yes))` and `(pin_names … (hide yes))`.
- **Typed views are snapshots.** After a raw edit, a typed `Schematic` over the same tree is stale until rebuilt (`invalidate_cache()`).
- **Repeated pin numbers.** kiutils' pin dict keeps one `(pin …)` entry per number on a placed symbol; the prototype reproduced that for parity. Keep it in the port; a change is a separate, listed commit like E2.
- **Typed `PCB` defaults (if anyone reaches for it).** Coordinates rebased onto the Edge.Cuts minimum corner (board graphics not); absent drill reads 0.0, absent `pinfunction`/`pintype` and zone name read `''`, absent stackup material/epsilon read `''`/0.0; oval drills read 0.0 with the size in `drill_size`; a zero zone clearance reads 0.2; custom-pad anchor and primitives aren't modelled; single-layer zones have `layer` and empty `layers`; zones have no back-reference to their raw node. The raw readers avoid all of these.
- **`modify.annotate_components`** finds `annotate.py` through `root.parents[3]`, which fails on a scratch root. The port takes it from `Path(__file__)`.

**Regression harness (Phase 4).** It's committed under `tools/kicad-regress/` and built from the Phase 1–3 scratch scripts (`run_refset.sh`, `refhash.py`, `cmp_ref.sh`, `rawcmp.py`, `netconn.py`, `svgstrings.py`, `tokcount.py`, `treeeq.py`, `erc_split.py`). If they're no longer in the scratchpad, it's rebuilt from the methods in SESSION Worker #1–#3 Notes. It makes fresh `git archive` copies (v8 at a given ref, v7 at `c2acffc`), each with `hardware/pcb-main/resources` beside it. Its run roots have fixed-length names (`extract.py` prints the netlist byte count, and the netlist carries the path). It runs the tools from the working tree or from a worktree at a given ref, with a given Python and `KICAD_CLI`. Comparisons are normalized hashes, a structural netlist compare, ERC/DRC counts by type with setup items split out, plotted strings per sheet, and token census and tree equality. kicad-cli 10 never runs inside the repo (HAZARDS `.kicad_prl`).

**Converting the format.** kicad-cli 10.0.8 has upgrade commands (9.0.4 doesn't): `kicad-cli sch upgrade [--force] <file>` and `kicad-cli pcb upgrade [--force] <file>`. Both rewrite the file in place (no output option) and need no GUI. `sch upgrade` converts only the file it's given, not the sheets under it: on a scratch v8 copy, upgrading the root left the four child sheets at `20250114`. So run it on every `.kicad_sch` in the project (root and each child); a second run prints "Schematic file was not updated". Format versions seen (Phase 1 probe): schematic 20250114 → 20260306, board 20241229 → 20260206. `pcb upgrade` also rewrote the `.kicad_prl`; the `.kicad_pro` was left untouched. Run it only on copies (the command overwrites its input). Scratch copies live in the session scratchpad and are never made from v7's working tree by a GUI open. Make them with `git archive c2acffc hardware/pcb-main/kicad hardware/pcb-main/resources | tar -x -C <scratch>`. Phase 3: the conversion itself is netlist-neutral (kicad-cli 10's netlist of an unconverted and a converted copy are identical).

**kicad-cli 10 differences the tools must absorb (Phase 3).**
- **`pinfunction` gets `_<pin number>` appended** in both netlist formats, on KiCad 9 and 10 files alike (`IO48` → `IO48_25`). `tools/schematic-context/extract.py:332` reads it from the kicadxml netlist, so circuit-context pin names change once `KICAD_CLI` is 10. A plain strip of a trailing `_<n>` is ambiguous when a pin name really ends that way. Phase 12 fixes it: strip only `_<that pin's number>`, or read pin names from the parsed symbol.
- Net `class` follows the `.kicad_pro` patterns (9 wrote `Default`); root components' `Sheetname` is the project name; sheet numbers follow page numbers; `(datasheet "~")` is dropped; `units`, `groups` and `variants` are added. No tool reads these today (grep).
- New warnings: ERC `same_local_global_label` (v8: 5, v7: 3), and DRC field parity between footprint and symbol fields (v7: R2 `ai_block`, +1). Neither is a design change.

**Scratch roots for the checks (Phase 4).** `layout_check.py`'s baseline is keyed by the sheet's repo-relative path, so `--root <scratch>` finds no baseline (Worker #1 Notes). Phase 4 keys it by the path relative to the project root, so a scratch copy checks against the committed baseline. `v8_*.py --check` and `v8_project_setup.py --verify` are hard-wired to the working tree. They gain `--root`, so they can run on scratch copies and never run kicad-cli 10 in the repo. On the working tree the output must not change.

## Rejected Approaches
- Replan inside v8-debug-board: the tooling serves every board, v8's BRIEF constraint line would have to change from inside v8, and its SESSION and TASKS are already long. The user chose a new initiative (2026-11-07).
- Upgrading KiCad in place (replacing 9.0.4): no rollback, and KiCad-9 baselines couldn't be re-made after the change.
- Migrating every board to KiCad 10 now: v7 can't be re-saved, and the sensor and power-supply boards have no active work. The tools must keep reading KiCad 9 files instead.
- Switching the global `python3` to 3.13: the lab pre-commit hook and lab tools run on it, so it would be an unrelated risk. Use a tools-only venv.
- Staying on Python 3.7 for the KiCad tools (G2, OQ-1): 3.7 is EOL, and kicad-tools needs ≥ 3.10. Phase 2 showed the 3.13 venv gives identical outputs.
- Extending the kiutils shim to KiCad 10 (G2, OQ-2): Phase 3 recommended it (one schematic flag, `show_name`, plus three board-read patches). The user chose the full replace: the shim's cost recurs with every KiCad release, and any loss nobody has found yet is silent.
- kiutils plus the shim for schematics, with kicad-tools for board reads only (G2): that means two parsers to maintain. The user chose one.
- kicad-sch-api as the schematic parser (G2): its save rewrites embedded library symbols. On v8 that took the netlist from 296 to 283 components and 158 to 154 nets (Phase 3, Worker #3 Notes).
- Port on kicad-tools' typed API, with the raw layer for the gaps (G2a option a): the typed layer can't edit or remove anything, its adds and `embed_lib_symbol` differ from `modify.py` or lose data, and the typed `PCB` changes six kinds of board value silently (Phase 5, Worker #5 Notes).
- Stop and reopen OQ-2 (G2a option c): every public `modify.py` operation worked on the raw layer with preport-identical results, so nothing kicad-tools lacks blocks the port.
- Plain kicad-tools save (OQ-7 option 1): about +548/−1,467 lines of whitespace for a one-Value edit on a 13,000-line sheet, and a whole-file rewrite of any file in kiutils format.
- Plain save, then a kicad-cli 10 re-save (OQ-7 option 2): exact KiCad layout, but KiCad 10 files only (kicad-cli 9 has no `upgrade`, and 10 would convert a 9 file), one kicad-cli call per saved file on a copy outside the project, and it ties the I/O module to the installed KiCad.
- Splice save plus the kicad-cli 10 re-save for KiCad 10 files (OQ-7 option 4): exact layout on 10 isn't worth option 2's costs on top of a +4/−8 diff.
- Porting `esp32_integration.py`, `esp32_integration_phase2.py` and `route_esp32.py` (G2a retire list): nothing calls them and they can only edit v7, which is never re-saved.
